# E2026 Q3-2.5 — Public alignment provenance sources

Audit date: 2026-09-24. Repositories were shallow-cloned for read-only source review and pinned to the commits below. No public MOSEI feature bundle, raw video corpus, or sentiment labels were downloaded. Current clone revisions were obtained from the repositories' default `main`/`master` refs and `git ls-remote`.

## Finding

Attachment4 is **structurally highly consistent with** the MMSA/Self-MM MOSEI aligned feature family, but available evidence does not confirm the attachment's source commit or file lineage. The released MMSA/Self-MM objects are split-level pickles with known aggregate checksums and source IDs (`video_id$_$clip_id`). Attachment4 contains 20 per-sample pickles whose IDs are only `01`–`20`, with no original source key, provenance record, or upstream checksum. Matching fields and dimensions are not a cryptographic or procedural link.

## What can be said about `aligned_50`

- **Observed Attachment4:** every sample has `[50,768]` `text`, `[50,74]` `audio`, `[50,35]` `vision`, and `[3,50]` `text_bert`. The mask row defines a true prefix; valid lengths are 13–50. `text_bert` stores token IDs, mask and segment IDs. No per-sample slot times, word boundaries, frame indices, segment map, `align`, or source IDs are stored.
- **Tokenization reproduced:** pinned fast `bert-base-uncased` tokenization with lowercasing, `[CLS]/[SEP]`, right truncation at 50, and right padding to 50 reproduces input IDs, attention masks and type IDs exactly for all 20 samples. This fixes observed tokenization behavior; it does not establish the provenance of the 768-D text features.
- **Word/token/segment rule:** the public MMSA release is described as aligned word-level data, and common CMU word-aligned recipes average audio/vision features over word intervals. BERT WordPiece token slots add subword granularity and special tokens; MMSA-FET shows one way to copy a word's nonverbal pooled feature to all of its WordPieces. No exact producer source confirms that this Attachment4 uses that same expansion rule.
- **Padding/truncation to 50:** Attachment4's token arrays prove a 50-slot right-padded/right-truncated representation for `text_bert`; samples 07 and 18 fill all 50 slots, while the rest carry mask-zero suffixes. Public MMSA/Self-MM repositories publish files/checksums but do not include the generator for that exact MOSEI `aligned_50.pkl`. Their generic preprocessing snippets must not be substituted for its unprovided recipe.
- **Audio 74 / vision 35:** dimensions match the well-known COVAREP/FACET feature family and Self-MM's MOSEI config. MMSA-FET's example is a different configurable extractor. Attachment4 contains no extractor names or feature metadata, so family assignment remains a strong hypothesis rather than verified provenance.
- **Timestamp retention:** SDK CSD data have intervals; public aligned pickle schema does not list them. MMSA-FET can retain an `align` list, but the Attachment4 pkl does not. No intermediate file accompanying this task links its sample IDs to CSD IDs or timestamps.

## Grounding consequence

`text_bert` slot → BERT token → raw character offsets is **VERIFIED** against the pinned tokenizer. P2's text contribution is applied to 768-D `text` feature rows, and the exact attachment producer has not been identified, so `text` feature-row → token is **UNVERIFIED**. Audio and vision rows lack both producer provenance and original time keys, so their aligned slot → seconds/frame map is **UNVERIFIED**. This is why the integrated evidence API returns the token-span mapping only as a diagnostic and leaves P2 `text_fragment`, audio seconds, and video frame fields null.
